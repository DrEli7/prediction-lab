# 可用于简历的项目介绍

建议项目名称：**数字货币与美股多资产方向预测研究平台（Prediction Lab）**

技术栈：Python、NumPy、Pandas、SciPy、PyTorch、Kronos、经验贝叶斯、时间序列验证、Bootstrap、GitHub。PyTorch/Kronos 属于本机研究阶段，公开轻量交付运行统计模型，无需 GPU。

## 简历精简版

**Prediction Lab｜多资产时间序列预测与可复现评估**  
项目地址：https://github.com/DrEli7/prediction-lab

- 面向 BTC、ETH、SPY、QQQ 构建 5/20 日方向预测研究流程，实现时间衰减先验、波动率/趋势状态经验贝叶斯模型及滚动多数基线。
- 建立严格标签成熟约束与统一评估口径，在 4 资产 × 2 期限 × 64 起点的 512 条完整历史样本上比较模型，结合宏平均平衡准确率、Brier、时间块 Bootstrap 和多重检验控制评估效果。
- 完成本机 Kronos 模型适配、训练瓶颈排查与完整测试；交付保留统计模型、1,536 条冻结预测、源码哈希验证、离线推理入口及研究交接文档。
- 统计模型在该历史样本上达到 **59.18%** 方向准确率，旧版本为 **58.79%**，并公开保留 **59.38%** 简单基线，避免将历史成绩表述为实盘收益或稳健超额能力。

## 面试时应能解释

1. 为什么训练标签必须在信号时间前成熟，为什么 20 日重叠标签不能当作独立样本。
2. 整体准确率、8 单元宏平均平衡准确率与 Brier 分别衡量什么；上涨基率为什么会造成表面高准确率。
3. 600/756 bar 窗口、时间衰减与 Beta/层级平滑如何实现，以及为什么这批统计模型仍未胜过简单基线。
4. Kronos 在本项目中实际完成了哪些训练和验证、为什么结果没有被推广、性能优化和算法效果之间有什么区别。
5. 哪些实现由自己完成，哪些在 AI 编程工具辅助下完成。不要把未能独立解释的细节写成个人独立研发成果。

不建议写“实盘胜率 60%”“稳定盈利”“显著超越基线”或“自主研发 Kronos 大模型”。这些都没有本项目证据支持。若主要工作是组织 AI 辅助研发，可在面试中明确说明工具使用和自己负责的需求、实验判断及验收部分。
